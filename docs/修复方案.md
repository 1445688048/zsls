## 第一批 P0:页面级阻断缺陷

### #1 export.js 语法错误
把 wx.showModal 的 content 写成完整单行字符串,两段文案用加号拼接:
content 行改为: 引号包裹的「PDF 导出功能开发中,请使用原文查看或脱敏查看功能。」+ (res?.message || 空串)
验证: 开发者工具重编译该页不再报 SyntaxError。涉及文件仅 miniprogram/pages/export/export.js 一处字符串。

### #2 tabBar 页跳转断裂
根因: detail 同时是 tabBar 页,wx.navigateTo 打不开 tabBar 页且其不收 URL 参数。tabBar 合法数量为 2~5,不能简单把 detail 移出了事。
推荐做法(switchTab + storage 传参):
1. 新增 utils/casenav.js 的 goToCase(caseInfo): setCurrentCase(caseInfo) 后 wx.switchTab 到详情页;
2. detail.js 增加 onShow: 从 getCurrentCase() 读 caseId,与 data.caseId 不同则 setData 并 loadCase(onLoad 之后每次切 tab 都触发,替代参数传递);
3. 替换三个调用点: index.js onGoToCase、case/create/create.js 创建成功后跳转、chat.js onNavigateToCase,统一走 goToCase 或 switchTab,全部去掉问号参数;
4. 边界: Storage 无 currentCase 时详情页显示空态引导「去创建案件」,不报错。

### #3 SSE 流式回复不上屏
根因: request.js 的 Promise 封装拿不到 chunked 流,chat.js handleStream 是空壳。
改法: chat.js 不再借道 request.js 发流式消息,直接调 wx.request 拿 task,注册 task.onChunkReceived(res => ...) 增量渲染。要点:
- 维护跨 chunk 字节缓冲,防止多字节汉字被截断;找最后一个分隔序列(两个换行字节)切出完整事件,余量留给下轮;
- UTF-8 解码优先 TextDecoder,低版本基础库内置约十几行的 utf8Decode 兜底函数;
- 按 SSE 规范解析: 以两个换行分事件,事件内所有以 data: 开头的行去前缀后按换行拼接为增量文本(服务端 Flux 遇内容自带换行会拆成多个 data: 行);
- 追加到最后一条 assistant 消息,setData 做 100ms 节流;请求结束保存完整文本。
顺带修复同页滚动: 消息区换 scroll-view(scroll-y + scroll-into-view 绑定最后一条消息 id),替换当前无效的 scrollIntoView 调用。request.js 只负责普通接口并补 timeout(见 #18)。

### #4 语音输入三重失效
方案A 修好: 
1. app.json 插件改官方《同声传译插件》: provider 用官方公开的 wx069ba97219f66d99、version 用 0.x 系列(提交前在小程序后台添加插件界面核对最新版本号);project.config.json 内重复 plugins 字段删除;
2. chat.js 用 requirePlugin("WechatSI") 取插件,getRecordRecognitionManager() 得 manager 存 this 上复用;onRecognize 回调更新 inputText,start({ lang: zh_CN });先 wx.authorize(scope.record) 申请录音权限;
3. permission.scope.record 描述保留即可,真实授权时机交给 authorize。
方案B 止血: 隐藏语音入口,Bug 入 backlog。无论选哪条,都必须同时做 #20。

### #5 隐私弹窗门禁失效
app.js 在 onLaunch 时 redirectTo 尚未加载好的首页无效。改为在 index 页 onShow 第一行拦截: 未同意则 wx.reLaunch 到 disclaimer 并 return,不发起业务请求。disclaimer.js 改用 storage 助手 setPrivacyAgreed()(key 单点定义)。提审前可再接入微信官方隐私协议能力作为双保险。

## 第二批 P1:安全加固

### #7 真登录 + JWT + 越权防护(IDOR 收口)
四步走:
(1) 真登录: AuthController.login 用 RestClient(Spring 7 自带)调微信 jscode2session(appid/secret/js_code/grant_type 四参),鉴权失败抛业务错误;拿到 openid 后 findByOpenid 无则建用户,签发 token 返回 userId;
(2) JWT 工具: 加 jjwt 0.12.x(api/impl/jackson 三件)。注意 HS256 要求密钥至少 32 字节——现默认 secret 只有 26 字节会直接抛异常,必须更换为 32 字节以上默认值并继续支持环境变量覆盖(此为功能性要求,与 #6 密钥处置无关)。签发 subject 存 userId,过期按配置 7d;校验解出 userId;
(3) 统一拦截器: 新增 AuthInterceptor——非 HandlerMethod 与 OPTIONS 预检放行,白名单(/auth/login)放行,其余校验 Bearer token 失败返 401,成功 req.setAttribute(userId),WebConfig 注册;提供 AuthContext.userId() 静态助手统一读取;
(4) 全链路去硬编码 1L: CaseController 的 create/list 用当前用户;案件 get/update 及 Chat/Timeline/Export 相关接口先查案件再比对属主,不一致返回 404(不暴露存在性)。抽 CaseGuard.assertOwner(caseId, userId) 供复用。前端配套: request.js 收到 401 先静默重登一次重放原请求,再失败才清 token 回首页。

### #8 CryptoUtils(AES/ECB + 密钥长度非法)
当前是死代码,建议随 #21 直接删除。将来需要时按规范重写: AES/GCM/NoPadding + 随机 12 字节 IV + SHA-256 派生 32 字节密钥,输出 Base64(iv 拼接密文),解密先切前 12 字节还原 IV。绝不使用 ECB。

### #9 H2 Console 关闭对外
主配置默认 spring.h2.console.enabled=false 并删除 web-allow-others=true;新增 dev profile 才 enabled=true 且仅本机访问;prod profile 永不含该项(结合 #22 的 profile 拆分)。

### #10 CORS 重构
三处一起修: 删除全部 7 个 Controller 上的 @CrossOrigin;WebConfig 映射由斜杠 api 斜杠双双星(受 context-path 影响永远匹配不到)改为 servlet 相对路径的 /**;allowCredentials(true) 必须搭配 allowedOriginPatterns 而非 allowedOrigins 通配符。dev 默认通配 patterns,prod profile 强制白名单环境变量 PALMLAWYER_CORS_ALLOWED_ORIGINS。小程序真机请求不走 CORS,CORS 仅服务开发调试网页。

## 第三批 P2:核心逻辑补全

### #11 Agent 编排接入实际对话链路
现状四个组件全是死代码,对话链路无系统提示词、无免责声明、事实不回写。改造 chatStream 为真正编排器:
1. 载入 session 与关联案件,PromptBuilder.build(case) 作为 SystemMessage 首条;
2. 对话历史改从 DB 取最近 20 条窗口(见 #12),拼入消息序列后追加本轮 UserMessage;
3. 出口用 Flux.concat(模型分片流, Flux.just(免责声明尾部帧)),保证上屏与落库都带免责声明,兑现系统提示词的合规承诺;
4. doOnComplete 里顺序执行: 保存 assistant 消息 → FactExtractor 回写 factsJson → EvidenceAdvisor.advise 结果写日志(供追问后续使用);每个子步骤独立 try/catch,局部失败不得中断已流出的回答;
5. 法规能力过渡方案: 构建 prompt 前用 lawService.search 以本轮用户输入取 top3 法条拼进系统提示词「本题参考法条」区,MVP 无需 Function Calling;LawSearchTool 的工具注册留作后续迭代。接线完成后 CaseAnalysisTool 等死类按 #21 清理。

### #12 会话历史内存化 + 并发不安全
废弃内存 ConcurrentHashMap 缓存,DB(chat_message 表)为唯一事实源: 每轮读最近 20 条窗口构上下文(现有查询已按时间排序,代码取尾窗);DELETE /history 改为真删 DB 记录使行为与方法名一致。一次性消除并发修改 ArrayList、内存无限增长、重启失忆三个问题。性能有压力时再叠加带 TTL 的只读缓存。

### #13 EvidenceAdvisor 条件求值顺序 bug
evaluateCondition 把不等分支提前到等值分支之前(现在含 != 的条件先命中等值的 contains 判断导致字段名被截断恒返回 false);等值切分限定只切一次(indexOf 或 split 限长参数)防值中出现等号时数组越界。对 yaml 已有的不等条件补一条单测锁定回归。

### #14 FactExtractor 结构不一致 + 静默失败
1. 统一 factsJson 值形状为 { value, confidence }: extract 每次 put 都包装成该形状(value 由 JsonNode 还原标量或对象,confidence 缺省 LOW);提供读取兼容函数 unwrapFact 给 EvidenceAdvisor 与历史数据共用;data.sql 已是该形状可作基准;
2. extractJsonBlock 先剥代码围栏标记;花括号做栈深扫描提取所有顶层平衡块,倒序尝试解析直到成功;
3. 解析失败的 catch 从静默吞掉改为 log.warn 带 FACT_EXTRACT 前缀,让提取率可观测。

### #15 证据采集闭环断裂
后端新增: POST /cases/{id}/evidence 上传(multipart 落盘到 storage.local-path 下按案件分目录,元信息追加进 evidenceRefs;保存路径做穿越清洗)、PUT /cases/{id}/evidence/{refId} 更新 collected。前端 evidence.js 选完媒体即上传拿 refId 回填列表,收集/删除同步 PUT。元素结构固定: refId/name/fileType/size/collected/uploadedAt。

### #16 法律之星集成空壳
1. LawStarClient 实现真实 HTTP(RestClient POST + 按供应商文档放置 api-key 请求头,超时 connect 3 秒 read 10 秒),失败 log.warn 后返回空列表;
2. LawStarCacheService 启用 law_cache 表(键为 sha256(query+region)),命中未过期直接回,否则调用后写缓存,LawCacheMapper 就地复活;
3. 显式降级: /law/search 响应增加 source 字段(mock 或 lawstar)透传前端,mock 时显示「示例数据」角标,法律场景不冒充真实检索;
4. 过渡备选: 若短期无供应商契约,先把常用法条灌入 domain_knowledge_vector 做模糊匹配检索,同样带 mock 标记。

### #17 PDF 导出假实现
引入 openhtmltopdf-pdfbox 1.0.10: resources/fonts 放思源黑体一款 TTF 注册字体解决中文渲染;ExportService 用 HTML 模板渲染案件标题/事实表/时间轴/引用法条/免责声明为 PDF 写入存储目录;redact=true 先对手机号与身份证正则打码;新增 GET /files/{caseId}/{filename}(属主校验 + 路径清洗)供下载,downloadUrl 返回真实地址;前端 export.js 改 downloadFile 加 openDocument 预览;README API 表同步更新。估算 1~2 人日。

### #18 登录竞态 + 请求无超时
1. App 暴露幂等 ensureLogin(): 首次生成 login Promise 并缓存,失败也 resolve 由 401 兜底;各页面首个请求前 await getApp().ensureLogin();
2. request.js 增加 timeout 15000,fail 分支区分超时给专门提示;
3. 401 流程: 静默重登一次并重放原请求,再次 401 才清 token reLaunch,加标志位防循环。

### #19 时间轴 JSON 整条读写丢数据
时间轴独立建表 timeline_event(event_id VARCHAR(36) 主键用 UUID 弃用毫秒时间戳避免同毫秒冲突;case_id 建索引;occurred_at/title/description/type 字段;H2 版 CLOB/TIMESTAMP,PG 版 TEXT/TIMESTAMPTZ 同步进 init.sql)。新实体与 Mapper,TimelineService 四个方法改为常规 CRUD(属主校验复用 #7 的 CaseGuard),对外 JSON 字段名不变前端零改动;case_profile.timeline_json 保留列位仅存历史不再读写。

### #20 隐私接口声明清理

### #21 死代码删除清单(git rm)
repository/CaseRepository.java;tool/CaseAnalysisTool.java;tool/TimelineTool.java;util/CryptoUtils.java(#8 结论删除);util/DateUtils.java;util/JsonUtils.java;miniprogram/utils/storage.js 的 isLlmConfigured/setLlmConfigured 连同 index.js 无用 import。视决策处理: LawSearchTool(不做工具注册则删);DomainKnowledgeVector 实体与 Mapper(不用 #16 过渡方案才删);LawCacheMapper(#16 启用保留)。删后 mvn clean package 全量编译验证。

### #22 双数据库方案矛盾
yml 拆 profile: 公共 application.yml 只留通用配置;dev 挂 H2 与 schema-h2.sql/data-h2.sql;prod 挂 PostgreSQL 且 sql.init.mode=never,生产建表交 Flyway 管理(V1 采用现 init.sql 内容),根治「切 PG 仍执行 H2 方言脚本启动必崩」。db/init.sql 中 llm_config 表与全局 LLMConfig 设计冲突,删除或标注弃用;README 切库指引同步重写。

### #23 H2ConsoleConfig 注释与行为相反
方法加 @ConditionalOnProperty(name=palmlawyer.h2-console.enabled, havingValue=true, matchIfMissing=false),catch 分支 log.warn 后返回 null 而非 rethrow;生产 profile 不含该属性时 Bean 不创建,既兑现注释语义,也消除移除 h2 依赖后的 ClassNotFound 崩溃面。

### #24 application.yml 冗余配置
删除: 整个 mybatis.* 配置块(实际生效的是 mybatis-plus.*)、指向不存在目录的 mapper-locations、global-config 三行 logic-delete-* 配置(没有实体含 deleted 字段)。

### #25 运维小项
server.port 支持 PORT 环境变量覆盖(缺省 8080);主 yml 加 logging.charset.console=UTF-8 解决 Windows 控制台中文乱码;docker-compose 端口绑定 127.0.0.1:5432:5432,密码变量改为必须显式提供的强制语法,弱默认口令删除。

### #26 storage 键不经助手直写
create.js 删除直写 currentSessionId(null) 一行,会话状态由 chat.js initSession 经 setCurrentSession 助手维护;全局搜索 setStorageSync/getStorageSync,除 storage.js 与 disclaimer 助手外不应有其他直写点。
