## 一、功能流线断点(建议修复)

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| F1 | **导出页无任何入口**：export 页只注册在 app.json，全项目无一处跳转 | 导出功能用户永远找不到，等于没做 | 在案件详情页增加"导出法律意见书"按钮(状态 READY 时高亮) |
| F2 | **案件创建页"案件描述"文本框未绑定**：create.wxml 的 textarea 无 value/bindinput，create.js 也无对应字段 | 用户输入的内容直接丢失，误导性 UI | 绑定并在提交时写入 factsJson._description，或删除该控件 |
| F3 | **详情页"法律意见"tab 是死内容**：永远显示占位文案"对话完成后自动生成法律意见"，没有任何数据来源(lawsJson 从未被写入) | 承诺的功能不存在，用户会疑惑 | 接入 Agent 输出(参考 #11 的法规注入结果)或在未生成前明确置灰"暂不可用" |
| F4 | **案件状态机不存在**：status 永远 COLLECTING，READY 永不出现(首页/详情/导出的"就绪"徽章形同虚设) | 状态语义失真，导出时机无法引导 | 在对话完成+证据达标后更新状态，或在导出入口改为无条件可用并去掉状态暗示 |
| F5 | **4 个组件全是死代码**：chat-bubble / disclaimer-modal / evidence-card / timeline-item 已实现但所有页面 usingComponents 均为空 | 增加包体积，维护噪音 | 接线使用或删除 |
| F6 | **首页 onRefresh 无绑定**：index.js 有 onRefresh 但 wxml 无对应控件(详情页有"刷新"按钮，首页没有) | 死方法；且首页数据无下拉刷新 | 加下拉刷新(enablePullDownRefresh)或删除死方法 |

## 二、布局/交互合理性瑕疵

| # | 问题 | 说明 |
|---|---|---|
| L1 | **发送按钮样式绑定用方法调用**：chat.wxml `{{inputText.trim() ? ...}}` —— WXML 表达式不支持方法调用，按钮可能永远灰色(点击仍可发送) | 改为 data.canSend 驱动 |
| L2 | **证据九宫格会显示空白卡**：点"标记已收集"的预设清单项(contract 等)会通过 PUT 在服务端创建无 url 的 ref，加载时全部进 evidenceList，`<image src=undefined>` 渲染空白 | loadEvidence 过滤无 url 的 ref，仅作 collected 标记 |
| L3 | **视频证据显示为静态图**：evidence-grid 一律用 `<image>` 展示，视频文件只显示空白缩略 | 加文件类型角标(图片/视频/文档)或视频缩略 |
| L4 | **事实要素展示原始 key**：detail 页 fact-label 显示 hasWrittenContract 这类字段名，领域插件里有中文 label 却未使用 | 前端应拉取 /plugins 或后端在返回时附带 label |
| L5 | **首页冷启动先发请求再过隐私门禁**：index.onLoad 直接 loadCases，onShow 才检查隐私，未同意用户会先触发一次请求和"未登录"报错 | 隐私检查前置到 onLoad/loadCases 内 |
| L6 | **tab 页绕过隐私门禁**："我的案件"tab 的 detail 页无隐私检查(门禁只在 index.onShow) | 未同意隐私也能进入详情页(无数据，危害小但流程不严) |
| L7 | **导出页文案过时**：export.wxml 仍写"PDF 导出功能开发中，暂支持原文查看" | 与已实现的 PDF 不符 |
| L8 | **时间轴按字符串排序**：eventTime 按字符串排，用户输入"3月1日"等非标准格式时顺序错乱 | 校验/统一日期格式或前端转 Date 排序 |
| L9 | **详情页刷新按钮 fixed 悬浮**：需确认在 iPhone 刘海屏/带 tabBar 环境不遮挡内容 | 人工目检 |
| L10 | **创建页领域选择后无"下一步"引导**：选完类型需手动填标题才能提交 | 小体验点，可选 |

## 三、整体合理性评价

- **主链路完整**：登录→建案→对话(流式+免责)→事实回写→证据收集→时间轴→导出，代码层面全部连通；
- **安全流线自洽**：401 自动重登重放、属主校验 404、dev/prod 双模式；
- **主要缺口集中在"次级页面触达"与"状态语义"**：导出无入口、法律意见无数据、状态不流转——都是 MVP 阶段的"半成品痕迹"，与缺陷报告 #11/#17 的历史一致；
- **组件层有过剩设计**：预留了 4 个组件却未接线，属前期脚手架残留。

## 四、需要你手动测试/人眼甄别的清单

### A. 布局与视觉(需真机+肉眼)
- A1 各页面在 iPhone SE / 主流机型 / 大屏安卓下的边距、字号、圆角是否协调；聊天输入栏在键盘弹出时是否被正确顶起(scroll-view 高度)；
- A2 详情页 5 个 tab 横向滚动与激活态配色；悬浮"刷新"按钮是否遮挡内容或与 tabBar 重叠；
- A3 证据九宫格 3 列在小屏是否过挤；视频缩略为空是否可接受；
- A4 时间轴红点/截止日红字/弹窗在矮屏是否溢出；
- A5 免责声明页内容滚动与按钮布局；tabBar 图标清晰度；
- A6 深色模式未适配(如需支持需补充 wxss 变量)。

### B. 功能流线(逐条走一遍)
- B1 冷启动：免责页→同意→首页→自动登录(dev 兜底)→空态引导；未同意时直接点"我的案件"tab 观察是否被放行(F6)；
- B2 创建案件：描述框输入内容→提交→(确认描述丢失 F2)→成功进详情→各 tab 切换；
- B3 对话：SSE 逐字上屏→末尾免责声明→返回详情→切"事实要素"tab 查看新字段(需点刷新)→"法律意见"tab 现状(F3)；
- B4 语音：授权弹窗→长按/点按识别→结果入输入框(需真机+插件版本有效，见 D1)；
- B5 证据：拍照/相册→上传进度→列表出现→杀掉小程序重进→仍在→标记收集→重进状态保持→删除；
- B6 时间轴：添加(分别试标准与非标准日期)→截止日红色→删除；
- B7 导出：原文/脱敏→下载→打开 PDF：中文是否渲染(见 D3)、脱敏是否生效、敏感字段是否真实打码；
- B8 断网/超时：各页面请求失败的提示是否友好、是否卡 loading；
- B9 401：本地把 storage 里 token 改成乱码→操作→应自动重登并重放成功；
- B10 双账号隔离：两台设备/两个微信号，A 的案件在 B 登录后应为 404/不可见；
- B11 重启后端后：继续同一会话对话，LLM 是否记得上文(DB 历史窗口)；
- B12 快速连点"发送"是否重复提交；连续创建多案件后首页排序与进入正确性。

### C. 接口层(可用 curl/开发者工具 Network 辅助)
- C1 /auth/login 无 code→400；伪造/篡改 token→401；
- C2 跨用户访问 caseId→404(不泄露存在性)；
- C3 /law/search 返回 source 字段(真实检索=lawstar，降级=mock)；
- C4 证据上传超大文件(>50MB)→友好报错；文件名为中文/含特殊字符→清洗后正常存储与下载；
- C5 H2 控制台：dev profile 可开、prod 关闭；8080 被占用时用 PORT 换端口。

### D. 依赖外部环境、代码已改但需现场确认
- D1 同声传译插件：provider=wx069ba97219f66d99、version=0.3.5 是否在"小程序后台-添加插件"里真实可用(版本号以平台显示为准)；
- D2 WXML 方法调用：确认 `{{inputText.trim()}}` 在你目标基础库的表现(若按钮常灰即为不支持，按 L1 修复)；
- D3 PDF 中文字体：本机走 arialuni.ttf 正常；部署到其他环境需放字体到 resources/fonts/ 或配 palmlawyer.storage.font-path，否则中文空白；
- D4 低版本基础库无 onChunkReceived 时，聊天走整包解析的兜底路径是否正常；
- D5 语音识别 60s duration 与 onRecognize 连续回填是否符合预期。

## 六、应用使用链路（当前实现全景）

```
【首次使用】
打开小程序
  ├─ 免责声明页(隐私政策)
  │    ├─ 不同意 → 退出小程序
  │    └─ 同意 → 首页
  └─ 首页 onShow：自动登录
       (wx.login code → 后端 jscode2session → JWT; dev 模式失败降级 dev_openid)
       → 领域卡片(LABOR 可选 / CONSUMER 置灰) + 我的案件列表(空态)

【创建案件】
首页 → 新建/选领域 → 创建页(领域 + 标题 + 描述[可选])
  → POST /cases(描述入 factsJson._description) → 成功
  → switchTab 案件详情页(当前案件写入 storage)

【案件详情页(我的案件 tab，也是 tabBar 页)】
5 个 tab：
  · 对话     → 聊天页
  · 事实要素 → 展示 factsJson(过滤 _ 内部字段)
  · 证据     → 证据管理页
  · 法律意见 → 引用法条(lawsJson)+免责声明 → 导出 PDF
  · 时间轴   → 时间轴页
悬浮刷新 / 首页下拉刷新

【对话链路】
聊天页：输入 → SSE 流式发送 → 逐字上屏 → 免责声明尾帧
  后端编排：PromptBuilder 系统提示词 + DB 最近20条历史 + 法条 top3 注入
  完成后：保存消息 → FactExtractor 回写事实 → mergeLawRefs 法条落库
           → CaseStatusService 状态重估
语音输入：授权(scope.record) → WechatSI 识别 → 回填输入框

【证据链路】
证据管理页：
  必要/增强清单 → 标记收集(PUT 持久化)
  拍照/相册/录像 → 逐张上传(POST multipart → 落盘 uploads/ + evidenceRefs 回写)
  → 列表展示(仅真实上传文件) → 预览 / 删除(DELETE)
  每次变更 → 状态重估

【时间轴链路】
时间轴页：添加事件(日期/描述/类型/截止日)
  → UUID 落库 timeline_event 表 → 按时间排序展示 → 删除

【导出链路】
详情页·法律意见 tab → 导出页：
  原文 / 脱敏 → POST 生成 PDF(openhtmltopdf + 中文字体，脱敏手机号/身份证)
  → downloadFile → openDocument 预览 / 转发

【案件状态机】(自动流转,只升不降)
COLLECTING ──(事实要素≥3)──▶ ANALYZING ──(上传证据≥3)──▶ READY
  触发点：每次对话完成、每次证据上传/标记/删除

【横向支撑】
· 鉴权：JWT 7天；401 → 静默重登一次并重放原请求，再失败清 token 回首页
· 越权防护：案件/会话/时间轴/证据/导出全部属主校验(404 不暴露存在性)
· 持久化：H2(dev)/PostgreSQL(prod) + 证据文件落盘 uploads/
· 隐私：免责声明门禁(首页/详情 tab 双拦截)、录音权限按需授权
```
