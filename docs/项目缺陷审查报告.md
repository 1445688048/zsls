# 掌上律师 MVP 1.0.0 缺陷审查报告

> 审查范围：backend/（Spring Boot 4 + Spring AI + MyBatis-Plus）、miniprogram/（原生小程序）、配置与数据库脚本。
> 严重程度定义：🔴 严重=功能不可用或重大安全风险；🟠 高=功能/安全缺陷；🟡 中=逻辑或一致性问题；⚪ 低=工程卫生。

---

## 一、严重（🔴）

### 1. export.js 存在 JavaScript 语法错误，整页无法编译
- 位置：miniprogram/pages/export/export.js 的 onExportPdf 中 wx.showModal 的 content 字符串。
- 该字符串字面量内含裸换行（已做字节级验证，LF 字节出现在引号内），属于未闭合字符串，页面加载即抛 SyntaxError，导出功能整体不可用。
- 修复：改写为单行字符串，或使用数组 join / 反引号模板字符串。

### 2. 案件详情页是 tabBar 页面，却全程用 navigateTo 跳转 → 流程断裂
- app.json 把 pages/case/detail/detail 注册进 tabBar，但 index.js(onGoToCase)、case/create/create.js(创建成功后跳转)、chat.js(onNavigateToCase) 都用 wx.navigateTo 且携带 ?id=/caseId 参数。
- wx.navigateTo 不能打开 tabBar 页面（必然失败）；且 tabBar 页无法接收 URL 参数。用户创建案件成功后根本进不了详情页。
- 修复二选一：把 detail 移出 tabBar 变普通页面；或保留 tab 身份但全部改用 wx.switchTab + storage 传参（switchTab 同样不能带参数）。

### 3. 聊天流式回复前端永不显示
- utils/request.js 用 Promise 封装 wx.request，不支持 chunked 流式数据；enableChunked:true 时数据须经 requestTask.onChunkReceived 逐块回调处理，Promise 版本拿不到流。
- chat.js handleStream 是空实现（注释自认“简化处理”）。结果：用户消息发出、后端正常入库，但助手回复永远不上屏。
- 修复：chat.js 直接持有 wx.request 返回的 requestTask，注册 onChunkReceived 解析 SSE data: 行并增量渲染。

### 4. 语音输入三重失效
- chat.js 使用 wx.requirePlugin("translating-plugin") —— 小程序没有 wx.requirePlugin 这个 API，正确的是全局函数 requirePlugin("WechatSI")，当前调用恒为 undefined；
- app.json/project.config.json 插件 provider 写的 wx4b7aa35f72c9a6a6、version 3.2.1 —— 官方《同声传译插件》provider 为 wx069ba97219f66d99，版本号为 0.x 系列，当前配置无法添加插件；
- 该插件真实 API 是 getRecordRecognitionManager()（start/stop/onRecognize），不存在 startTranslating({lang})。
- 结论：语音输入按钮在任何环境下都只弹“插件未配置”。建议修正配置与 API，或先下架该入口。

### 5. 隐私弹窗门禁基本失效
- app.js 在 App.onLaunch 里 wx.redirectTo 跳免责声明页。onLaunch 时首页尚未加载完成，导航会失败/被忽略，隐私确认可被完全绕过。
- 修复：disclaimer 设为入口页或在 index onLoad/onShow 中拦截。

## 二、高危安全问题（🟠）

### 6. 真实密钥明文提交进 git（含历史）
application.yml 被git 跟踪，硬编码了三个真实密钥：LLM API Key(sk-mWpi...)、微信 AppSecret(1b19...)、法律之星 API Key(e3bf...)。
处置：立即在对应平台吊销/轮换全部三个密钥；配置只留环境变量占位不给默认值；必要时 git filter-repo 清理历史。

### 7. 认证是假的，所有接口实际无鉴权（IDOR）
- AuthController.login 不调微信 code2session，固定返回 token "dev_token_1" 和 userId=1；/auth/check 恒 authenticated=true。
- 所有 Controller 不校验 Authorization，所有业务 userId 硬编码 1L。
- 后果：任何人可读写任意 caseId/sessionId 数据；不同用户共享 userId=1 数据集，毫无隔离。JWT secret 配置存在但全项目没有签发/校验 JWT 的代码，也没有 Spring Security 或过滤器。

### 8. CryptoUtils：ECB 模式 + 密钥长度非法（死代码，启用即炸）
- AES/ECB 无 IV；默认密钥长度 44 字节，AES 只接受 16/24/32 字节，一旦调用必抛 InvalidKeyException。
- 启用时改为 AES/GCM + 随机 IV + 32 字节密钥。

### 9. H2 Console 对外开放 + sa 空密码
web-allow-others: true 配合 sa 空密码和无鉴权 = 数据库裸奔。应默认 false 仅本地启用。

### 10. CORS 双重错乱
context-path=/api/v1 下 servlet path 不含前缀，WebConfig 注册的 "/api/**" 匹配不到任何端点（这套 CORS 从未生效）；实际生效的是控制器裸 @CrossOrigin（放行所有来源）。且 allowCredentials(true) 与 "*" 组合本身非法，真生效会在运行期抛异常。

## 三、功能/逻辑缺陷（🟠🟡）

### 11. Agent 编排链路与实际对话脱节（产品核心缺失）
实际链路 ChatController → ChatService.chatStream 中：无系统 Prompt、回复不带免责声明、事实不回写案件、证据建议不产出、法规工具从未注册给模型。设计中的编排器 AgentService.chat 及 PromptBuilder/FactExtractor/EvidenceAdvisor 均为死代码（仅被无人调用的 CaseAnalysisTool 引用）。
合规影响：提示词承诺“每次回复末尾必须附免责声明”，实际链路做不到——法律 AI 产品的实质性合规缺口。

### 12. LLM 会话历史仅存内存且线程不安全
ConcurrentHashMap 里放普通 ArrayList：并发同会话有并发修改风险；无限增长内存泄漏；重启后 DB 消息不回灌导致 LLM“失忆”；DELETE /history 只清内存不清 DB，接口语义不符。

### 13. EvidenceAdvisor 条件求值顺序 bug
evaluateCondition 先判 "=" 再判 "!="：形如 terminationType != '辞退' 的条件走进 = 分支后 field 被截成 'terminationType !'，查不到值恒返回 false，所有 != 适用条件失真。须先判 != 。

### 14. FactExtractor 数据结构不一致 + 静默失败
data.sql 既有的 facts 形如 {value, confidence}，提取却把 JsonNode 原样塞入（可能为标量），同一 map 混杂两种结构，detail.js 的 value?.value 解析丢值；extractJsonBlock 取首个 { 到最后一个 } ，混入其他花括号内容时解析必败且 catch 静默吞掉。

### 15. 证据采集闭环断裂
evidence.js onChooseMedia 只 setData 到本地，evidenceRefs 从不 PUT 回写后端，换页即丢；“已收集”状态也不持久化。

### 16. 法律之星集成是空壳
LawStarClient 固定返回空列表/占位文本“法条内容获取中”，api-key 从未使用；/law/search 无感降级 mock 法条、/law/article 返回假内容不告知来源；law_cache 表与 LawCacheMapper 全部闲置。

### 17. PDF 导出是假的
ExportService 返回 example.com/mock.pdf 占位链接；前端导出/预览按钮全是“开发中”toast。README 将其列为已有能力，建议标注未实现。

### 18. 登录竞态导致首屏报错
autoLogin 异步未完成时 index 已发请求，首启必现“未登录”；request.js 未设 timeout；401 清 token 后 reLaunch 到 index 又立即请求，存在循环隐患。

### 19. JSON 字段并发更新丢数据
timeline_json 等整条读-改-写无锁，并发写互相覆盖；事件 id 用 System.currentTimeMillis()，同毫秒冲突。

### 20. 隐私接口声明与实现不符（审核风险）
app.json 声明 chooseLocation/chooseAddress/scope.record，但全项目无对应 API 调用。声明未使用的隐私接口影响审核通过。

## 四、工程一致性/卫生问题（⚪）

21. 死代码清理清单：repository/CaseRepository、tool/ 三个 @Tool 工具、util/CryptoUtils|DateUtils|JsonUtils、mapper/DomainKnowledgeVectorMapper 与 LawCacheMapper、ChatService.chatWithSystemPrompt、storage.js isLlmConfigured 系列（index.js 还 import 未用）。
22. 双数据库方案矛盾：init.sql 有 llm_config 表（按用户自配 Key 的旧设计）与现行全局 LLMConfig 冲突；sql.init.mode=always 切 PG 后仍执行 H2 方言 schema/data(DATEADD)，启动即崩——README 切换指引不可行。
23. H2ConsoleConfig 注释称“注册失败不影响启动”，实际 rethrow IllegalStateException，移除 h2 依赖后应用直接起不来。
24. application.yml 残留无效配置：mybatis.* 与 mybatis-plus.* 重复；mapper-locations 指向不存在目录；logic-delete-field 无对应实体字段。
25. 运维项：曾发生 8080 占用启动失败；Windows 控制台日志中文乱码；docker-compose 弱默认口令且 5432 对宿主全网卡开放。
26. create.js 绕过 storage 助手直写 currentSessionId（null），与 chat.js 使用的 currentSession 键不一致。
